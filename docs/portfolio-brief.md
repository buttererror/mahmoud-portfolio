# Portfolio Brief

This document holds product and content direction for Mahmoud Ahmed's portfolio. It is a working brief, not a locked specification. Agents should use it as the current default and raise tradeoffs when a better direction appears.

## Project Goal

Build a professional portfolio website for Mahmoud Ahmed, a Front-End Developer focused on:

- React.js.
- Next.js.
- TypeScript.
- Dashboards.
- SEO.
- Performance optimization.
- Frontend deployment.
- Production-ready frontend delivery.

The portfolio should support job applications, LinkedIn, GitHub, and resume improvements. It should be a proof-of-work website for recruiters and hiring managers, not a fancy animation project.

## Positioning

Use this primary positioning consistently:

> Front-End Developer focused on React.js, Next.js, TypeScript, dashboards, SEO, and performance.

Supporting summary:

> I build production web applications, landing pages, and dashboard interfaces with a focus on clean UI, performance, SEO, and reliable frontend delivery.

Mention backend only as a growth area. Suitable wording:

> Currently expanding backend experience with Node.js, NestJS, PostgreSQL, and Prisma.

Do not present backend as professional backend experience. Do not describe Mahmoud as a Full-Stack Developer yet.

## Projects Page

The Projects page should present public-safe work only.

Include:

- Portfolio website.
- Cluster Point, only if cleaned and worth showing.

- Any polished React/Next.js demo created later.

Do not expose private company code or confidential implementation details.

## Writing Rules

Use clear, professional, recruiter-friendly language.

Avoid:

- Exaggerated claims.
- Buzzword-heavy writing.
- Empty marketing language.
- Overly fancy portfolio copy.
- Long paragraphs.
- Unverifiable claims.

Do not invent metrics. If metrics are unknown, use careful wording such as:

- Improved page performance scores.
- Helped improve technical SEO readiness.
- Supported faster page loads.
- Improved frontend delivery reliability.

## Design Direction

The design should be clean, modern, responsive, and recruiter-friendly.

Prioritize:

- Strong typography.
- Clear spacing.
- Good contrast.
- Fast page loading.
- SEO basics.
- Accessibility basics.
- Scannable case-study summaries.

Avoid:

- Heavy animation.
- Complex 3D effects.
- Overdesigned sections.
- Slow-loading visuals.
- Generic template feel.

## SEO Direction

Use clear title patterns:

- `Mahmoud Ahmed | Front-End Developer`
- `Renohome Website Case Study | Mahmoud Ahmed`
- `Projects | Mahmoud Ahmed`
- `Contact | Mahmoud Ahmed`

Descriptions should focus on React.js, Next.js, TypeScript, dashboards, SEO, and performance without keyword stuffing.

## README Expectations

Replace the starter README with a portfolio-specific README before deployment. It should explain:

- What the portfolio is.
- Why it exists.
- Tech stack.
- Main sections.
- How to run locally.
- How it supports Mahmoud's React.js and Next.js positioning.
- Live demo link when available.

Public repos shown or pinned from the portfolio should include clear READMEs with purpose, stack, features, screenshots when useful, live demo links when available, setup instructions, and notes on whether the repo is a portfolio project, job task, or public demo.

## Later Strategy

After the MVP is deployed:

- Improve the GitHub profile README.
- Pin only clean, useful public repositories.
- Clean Cluster Point only if it strengthens the profile.
- Build one focused React/Next.js demo repo only if more public proof is needed.
- Make a full-stack web app presentable later, after a meaningful vertical slice exists and private project details are generalized.
- Add the deployed portfolio to LinkedIn Featured.

## Final Principle

Every page should make this message obvious:

> Mahmoud is a React.js, Next.js, and TypeScript Front-End Developer who can build production UI, dashboards, SEO-focused pages, and reliable frontend experiences.
